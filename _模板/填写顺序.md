# AI 写卡参考顺序（强制）

无记忆开聊时：**先读本文件 + `写作规范.md`，再按下列顺序写文件**。  
不要跳步；不要把多类内容揉进同一个文件。

目标目录：`卡/<卡名>/`（从 `空白卡结构/` 对照应有文件）。

---

## 第 0 步 · 建夹与锁定创意

1. 若目录不存在：创建 `卡/<卡名>/`，按 `空白卡结构/` 补齐空文件骨架。  
2. 写入 `brief.txt`：定位、时代/场景、关系与冲突、语气与尺度（通用摘要，不写工具名）。  
3. 若用户只给了卡名、简述含糊：先用 3～5 条要点确认，再开写（用户说「直接写」则可推断）。

---

## 第 1 步 · 核心身份（平台 basic）

按此顺序，每写完一个对照 `写作规范.md` 同名章节：

| 序 | 文件 | 要点 |
| --- | --- | --- |
| 1 | `name.txt` | 角色名；考虑性别/文化/性格/身份暗示 |
| 2 | `tags.txt` | 发现用标签，逗号或空格分隔 |
| 3 | `description.txt` | **详细描述**：背景、经历、能力、关系；可用性别/年龄/性格/外貌/性癖结构 |
| 4 | `personality.txt` | 特质、情感、人际、价值观、行为、优缺点（可有矛盾） |
| 5 | `scenario.txt` | 环境、氛围、时间、人物、位置；**为开场铺垫** |
| 6 | `system_prompt.txt` | **可执行**扮演规则（语气/知识/行为/情感/互动/能力立场） |
| 7 | `creator_notes.txt` | **角色卡介绍，AI 不可见**：概述、玩法、禁忌、版本 |
| 8 | `creator.txt` / `character_version.txt` | 有则写，无则留空或 `1.0` |

---

## 第 2 步 · 世界书（平台 worldbook）

先常驻、后触发；控制常驻体积，避免每轮 Token 爆炸。  
**玩家设定（`{{user}}`）必须写成一条常驻世界书**，写法见 `写作规范.md`「玩家设定（常驻世界书）」。

| 序 | 路径 | 要点 |
| --- | --- | --- |
| 1 | `character_book/name.txt` | 常写「世界设定」 |
| 2 | `entries/001/` | **常驻** `constant=true`：世界观 / 与玩家的核心关系（短） |
| 3 | `entries/002/` | **常驻** `constant=true`：**玩家设定（`{{user}}`）**——身份关系、可覆盖的默认外貌/性格/称呼；写明「玩家另有设定时以玩家为准」 |
| 4 | `entries/003/` 起 | **触发** `constant=false`：人名、地名、道具、阶段等；必填 `keys.txt` |
| | `constant.txt` | `true`=常驻每轮；`false`=靠 `keys.txt` |
| | `keys.txt` | 非常驻必填触发词；常驻条可空 |
| | `content.txt` | 插入正文；001/002 宜短，勿把整本小说塞进常驻 |
| | `enabled.txt` | 一般为 `true` |
| | `name.txt` / `comment.txt` 等 | 002 建议命名「玩家设定」；备注仅给人看 |

若旧卡条目编号已占用：可把「玩家设定」插在靠前的常驻位，或新建下一条常驻，但**每张卡至少一条**启用中的玩家设定常驻条。

---

## 第 3 步 · 开场对话（平台 dialogue）

| 序 | 文件 | 要点 |
| --- | --- | --- |
| 1 | `chat_history.json` | 至少一段；**最后一条必须是 AI/assistant**；内容落在 `scenario` 里 |
| 2 | `first_mes.txt` | 与开场中 AI 首句一致（兼容导出） |
| 3 | `suggested_replies.txt` | 一行一条，**最多 5 条** |

---

## 第 4 步 · 图片 / 音色（可后补）

| 文件 | 要点 |
| --- | --- |
| `assets/` + `avatar_url.txt` | 有图再填；发布常要求头像 |
| `image_info.json` | 图库/封面，发布常要求至少一张 |
| `voice_settings.json` | 无音色则 `null` 或 `{}` |

---

## 第 5 步 · 自检（写完必做）

- [ ] 描述 / 性格 / 场景 / 系统指令 / 开场 / 世界书 **无互相矛盾**  
- [ ] `creator_notes` 没有写进会进模型的字段；系统指令足够可执行  
- [ ] 进模型字段对玩家/本卡角色优先用 `{{user}}` / `{{char}}`（见 `写作规范.md`），未无故写死玩家名  
- [ ] 已有启用中的**玩家设定常驻世界书**（建议 `entries/002/`），含关系约束 + 可覆盖默认，且声明玩家优先  
- [ ] 开场末条为 AI；建议回复 ≤5  
- [ ] 非常驻世界书有 keys+content；常驻（含 001/002）不过重  
- [ ] 未改仓库根目录 `_模板/`；未改 `publish/`  
- [ ] 向用户汇报：卡路径 + 已写文件 + 缺图/待上云事项  

---

## 顺序为什么这样

1. **brief → 描述/性格** 先定人，再定规矩。  
2. **scenario → 开场** 先定舞台，对白才贴地。  
3. **system_prompt 在性格之后** 规则服务性格，而不是反过来。  
4. **世界书在开场前** 常驻先稳（世界观 + **玩家设定**），再写触发词条与对白。  
5. **玩家设定进常驻世界书** 平台无独立 user 栏时，用常驻条补齐 `{{user}}` 默认与关系，避免开聊「玩家空白」。  
6. **creator_notes 靠后** 给人看的介绍，应总结已定稿设定。  
7. **图/音色最后** 不挡文案；无图也可先交文字卡。
