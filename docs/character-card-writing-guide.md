# 角色卡创作规范（对齐平台填写框说明）

来源：DZMM 创意工坊 `studio/edit` 前端 i18n（`zh-CN/studio.json`）。  
写卡、改卡、Agent 补全字段时，**以本文件与官网表单说明为准**，不要自由发挥成另一套「卡规范」。

字段落盘对照见 `docs/character-card-fields.md`。  
**Agent 冷启动请用**：仓库根目录 `_模板/`（含填写顺序与本规范副本 `写作规范.md`）。  
原始抽取（维护用）：`.probe-character-api/studio_zh_CN_field_help.json`。

## 总原则

1. **每个字段只写该框要求的内容**（见下方各节「应写什么」）。
2. **互相一致**：详细描述 / 性格 / 场景 / 系统指令 / 开场对话 / 世界书不要互相打架。
3. **角色卡介绍（`creator_notes`）给人看，AI 看不到**；其余会进模型上下文的字段要可操作、可扮演。
4. **校验底线**（平台会拦）：名称、头像、至少一张图库图；开场对话至少一段且最后一条为 AI；世界书非常驻条目要有触发词与内容；建议回复最多 5 条。
5. **进模型字段优先用占位符**（见下节「`{{user}}` / `{{char}}`」）；不要把玩家名写死进系统指令与世界书。

---

## `{{user}}` / `{{char}}`（占位符）

对齐 SillyTavern / `chara_card_v3` 常见宏。聊天侧若支持替换：`{{user}}` → 玩家昵称或人设名，`{{char}}` → 本卡 `name`。

| 宏 | 指谁 | 典型用法 |
| --- | --- | --- |
| `{{user}}` | 玩家 | 关系、称呼规则、开场里对玩家的叫法 |
| `{{char}}` | 本卡角色名 | 单人卡自称/第三人称；与 `name.txt` 一致 |

**必须优先使用（会进模型的字段）：**

- `description.txt` / `personality.txt` / `scenario.txt`
- `system_prompt.txt`
- `character_book/**/content.txt`
- 开场里**叙述关系**的句子（可用 `{{user}}`，避免锁死示例玩家名）

**可以写死真名的情况：**

- 配角、地名、势力名（本来就不是玩家/卡名）
- `creator_notes.txt`（给人看，可用示例称呼说明玩法）
- 开场对白若强依赖某个昵称的戏剧效果——可写死，但系统指令仍应用 `{{user}}`，并注明「开场默认昵称可改」

**多人 / 大世界 / RPG 卡：**

- 玩家一律 `{{user}}`
- `{{char}}` 只代表**卡本体**（常是世界名或 GM/旁白名），不要让各个 NPC 自称 `{{char}}`
- NPC 在世界书里用真名；系统指令写清「如何切换多角色台词」

**自检：** 发布或试聊前看一眼预览——若宏未被替换而原文露出 `{{user}}`，再改回具体称呼或换写法。

## 玩家设定（常驻世界书）

平台写卡**没有**独立的「user / 玩家人设」填写框；聊天里 `{{user}}` 往往只有昵称。  
本仓库约定：**把玩家侧设定写成一条世界书常驻条目**（建议 `character_book/entries/002/`），每轮注入，相当于补上 user 栏。

| 本地 | 要求 |
| --- | --- |
| `name.txt` | `玩家设定`（或 `{{user}}设定`） |
| `constant.txt` | `true`（常驻） |
| `enabled.txt` | `true` |
| `keys.txt` | 可空 |
| `content.txt` | 见下方应写什么 |

**应写什么（保持短）：**

1. **本卡必需的关系/身份**（例：`{{user}}` 是 `{{char}}` 的外甥，双方均已成年）  
2. **默认称呼**：角色如何称呼 `{{user}}`；`{{user}}` 如何称呼角色  
3. **可覆盖的默认**：性别倾向、年龄段、外貌一两句、气质——仅当玩家未另作说明时使用  
4. **覆盖规则**（必写一句）：玩家对人设/外貌/姓名的明确设定优先于本条目默认  

**不要写：** 替玩家决定每句台词；把完整 OC 长传记塞进常驻；与 `description` / `system_prompt` 打架的设定。

**示例结构（勿照抄剧情）：**

```
【玩家 · {{user}}】
- 关系：{{user}} 是 {{char}} 的晚辈亲属；寄宿其家。
- 称呼：{{char}} 称 {{user}} 为「小辉」或对方告知的名字；{{user}} 称其为小姨。
- 默认（可被玩家覆盖）：成年男性，身高约一七五，气质普通、略带少年感。
- 覆盖：若玩家或对人设另有说明，以玩家为准；勿强行改写其外貌与性别。
```

`creator_notes` 里可提示用户：「可改世界书『玩家设定』条，或开聊时自报人设。」

## 向导步骤（平台文案）

| 步骤 | 平台说法 | 用途 |
| --- | --- | --- |
| basic | 核心身份 | 名、详细描述、性格、场景、系统指令、角色卡介绍、标签、头像/图库 |
| dialogue | 开场对话 | 用户开始对话时展示的预设内容，可多组随机 |
| worldbook | 世界书 | 关键词触发词条，丰富上下文 |
| voice | 声优设置 | TTS |
| preview | 预览发布 | 校验后保存/发布 |

快速创建只做核心设定；专业模式解锁性格、场景、系统指令等。

## 角色名 `name.txt`

**标签**：角色名  

**说明**：名称会塑造 AI 人格，影响人对角色的第一印象，也会影响 AI 的自我认知与行为。选名时考虑：

- 性别暗示 → 影响对自身性别的表现  
- 文化背景 → 影响语言风格与知识范围  
- 性格特征 → 如强势、温柔等，可能影响行为模式  
- 职业或身份 → 影响对话态度与知识倾向  
- 特殊含义 / 典故 → 可能影响自我认知与价值观  

请确保名字准确反映期望的角色特征与背景。  

**示例占位**：`星月凌霄`

---

## 详细描述 `description.txt`

**标签**：详细描述  
**副说明**：角色的背景故事、经历、能力特长等详细信息  

**应写什么**：全面描述角色——背景故事、重要经历、能力特长、关系网络等，让他人能深入了解角色，赋予内涵与深度。

**可选插入模板**：

```
性别: 
年龄: 
性格: 
外貌: 
性癖: 
```

**示例风格**（平台 placeholder，可仿写结构，勿照抄设定）：

> 星月凌霄出生于一个古老的守夜人家族……白天是图书馆管理员，夜晚守护城市……与年轻警探既是盟友又是对手。

---

## 性格 `personality.txt`

**副说明**：性格特点、说话方式、行为习惯  

**宜覆盖**：

| 要点 | 说明 |
| --- | --- |
| 基本特质 | 内向/外向、乐观/悲观等 |
| 情感表现 | 情绪化还是理性克制 |
| 人际关系 | 友善、警惕、疏离等 |
| 价值观 | 核心信念与道德标准 |
| 行为模式 | 不同情况下的典型反应 |
| 优点和缺点 | 让角色立体 |
| 成长潜力 | 可选：性格可能变化的方向 |

**提醒**：复杂而有矛盾的性格往往更真实；避免完美无缺或过于单一。

---

## 场景 `scenario.txt`

**副说明**：角色所处的环境、时间和地点  

**宜覆盖**：物理环境、氛围（光/声/味）、时间、相关人物、角色在场景中的位置/活动、场景对角色的情感意义。  

**提醒**：须与背景故事和后续开场对话一致。

---

## 系统指令 `system_prompt.txt`

**副说明**：指导 AI 如何扮演和表现角色的具体规则  

**宜覆盖**：语言风格、知识范围、行为模式、情感表达、互动规则、特殊能力或限制、角色立场。  

**提醒**：清晰、具体、可操作；与背景和性格一致；避免空泛口号。可用编号条目。

---

## 角色卡介绍 `creator_notes.txt`

**平台标签**：角色卡介绍  
**关键**：面向用户；**AI 不会看到此内容**。

**宜覆盖**：角色概述、背景设定、互动指南（主题/禁忌）、特殊设定、版本信息、使用建议、注意事项。  

目标是帮助用户理解和使用角色卡，尽量提供有价值信息。

---

## 标签 `tags.txt`

详情页展示，帮助发现角色。本地可用逗号/空格分隔；平台上按回车、空格或逗号添加。

---

## 头像 / 图库

| 项 | 说明 |
| --- | --- |
| 头像 | 聊天头像；≤10MB；JPG/PNG/GIF/WebP；动图转 APNG |
| 图库 | 详情页封面可滑动图集；可调顺序；发布常要求至少一张 |

本地：`avatar_url.txt`、`assets/`、`image_info.json`。

---

## 开场对话 `chat_history.json`

设置用户开始对话时展示的预设内容，可多组供随机选择。  

**规则**：至少一段聊天记录；每段至少一条 AI 消息；**最后一条必须是 AI**。  

建议回复最多 **5** 条（`suggested_replies.txt`）。

---

## 世界书 `character_book/`

**步骤说明**：添加词条丰富上下文；对话出现特定关键词时触发。  

| 本地文件 | 平台含义 |
| --- | --- |
| `name.txt`（条目） | 条目名称 |
| `content.txt` | 触发后插入对话的内容 |
| `keys.txt` | 触发词（非常驻时必填） |
| `constant.txt` | 常驻：始终生效，无需触发词；适合世界观、**玩家设定**等每轮都要的内容 |
| `enabled.txt` | 停用则忽略 |
| `comment.txt` | 仅自己参考，不影响内容 |
| `priority.txt` | 多条同时生效时，值越小越先被模型看到（平台兼容提示：部分卡的自定义 priority 可能不生效，以插入顺序为准） |
| `position.txt` | 插入位置（角色描述头/尾、系统提示前/后、聊天历史、示开头/尾、开场白结尾等） |

**推荐条目顺序：** `001` 世界观/关系常驻 → `002` **玩家设定常驻**（见上节）→ `003+` 关键词触发。  

空世界书时平台提示：为角色添加背景知识与设定，让对话更丰富。本仓库写卡时**不要**省略玩家设定常驻条。

---

## 写卡时怎么用本规范

**填写先后顺序以 `_模板/填写顺序.md` 为准。**

1. 先写清 `brief.txt`，再按顺序填各字段。  
2. 每个文件对照本章对应小节；不要把性格写进系统指令，或把给人看的介绍写进 `description`。  
3. 世界书阶段务必写好 **玩家设定常驻条**（`{{user}}`）。  
4. 填完按填写顺序第 5 步自检。
